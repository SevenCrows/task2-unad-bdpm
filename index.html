Activity 2 NoSQL

Application of basic NoSQL principles

Objective

This activity aims to understand the structure of document-based NoSQL data using a Python dictionary as an equivalent representation of JSON, building the three employees as documents that are each extended with the Seniority (years at the company) and Country (country of origin) fields, so that the resulting set is finally written to the employees.json file using json.dump().

The document model

Each employee is modeled as a document with its own fields, including a nested field (Information, with Subject and Grade), which illustrates the central feature of the document-based NoSQL model, since its structure is flexible and can contain objects within objects unlike a relational table of flat columns, so that once Seniority and Country are added the set is serialized into employees.json with json.dump() using with open(...).

Activity 3 SQL NoSQL

Creation of SQL and NoSQL databases

Objective

This activity models the same purchase transaction information in the two storage paradigms in order to show their differences, representing it first in a relational database bd_compras with the cliente1_pedidos table and then as a document in cliente2_pedidos.json.

The core idea is to show the same data with a different structure, since the SQL model organizes it into flat rows and columns while the NoSQL model organizes it into documents with nested objects.

NoSQL model (document) NoSQL

The same information is represented in cliente2_pedidos.json with a nested structure in which each order groups the data into Customer, Product and Shipping objects, also including fields that the SQL table does not have (Product.Status, Shipping.Days, Shipping.LateDeliveryRisk), which shows an advantage of the document model by allowing richer and more flexible information to be stored.

Key difference between the two models

SQL Relational

The schema is fixed, with flat rows and columns in which each attribute corresponds to a typed column, which makes it ideal for uniform data and for queries with strict relationships and referential integrity.

NoSQL Document

The schema is flexible, with nested objects (Customer, Product, Shipping) that allow additional fields per document without altering a table, which makes it ideal for rich and variable information.
